## Part 1: Security

| ID | Sev | Finding |
|---|---|---|
| C1 | Critical (demo deploy) | Demo Vercel project with copied prod env hijacks the prod Telegram bot and routes real family reminders through the demo |
| H1 | High | Anyone can mint unmetered OpenAI realtime tokens; voice quota bypassed by re-calling `/session`; "text" tokens unmetered and upgradeable to audio |
| H2 | High | Unlimited Opus calls on `/api/ask` for any non-Life household incl. the 14-day trial any email gets; no rate limiting anywhere |
| H3 | High (demo data) | `reset_my_data` is not a full reset: categories duplicate each seed run, rehearsal chat stays, cron posts seeded recurring items mid-demo |
| M1 | Medium | `/api/assistant/end` replayable: Haiku cost + memory spam |
| M2 | Medium | Storage read policy trusts client-supplied `files.storage_path` |
| M3 | Medium | Seed hard-pinned to the prod project; guard weak against real accounts |
| M4 | Medium | This checkout is `vercel link`ed to prod project `rideff-life` |
| L1-L8 | Low/Info | see below |

**Already solid:** RLS on every `public` table with column-level UPDATE grants so `id/household_id/owner_id` can't change (`20261009000000_money_core.sql:180-185`); every SECURITY DEFINER sets `search_path=''` with revokes from `public, anon` (`rideff_v4.sql:444-448`, `assistant.sql:104-112`, `telegram.sql:111-116`); `billing_apply` service_role only (`fase_a_limits.sql:90-91`); Stripe signature verified (`api/billing/webhook/route.ts:16`); Telegram secret timing-safe (`lib/telegram/api.ts:18-22`); invite tokens and inbox keys stored hashed; no policy uses `auth.jwt()`/user_metadata; no service-role key in client code (`SUPABASE_SECRET_KEY` only in `lib/stripe.ts:10`, `lib/telegram/session.ts:15`); one private storage bucket `files` limited to `<household>/<uid>/` (`money_complete.sql:248-273`).

**C1.** `api/telegram/link/route.ts:16-22` picks origin from `APP_URL` then `VERCEL_PROJECT_PRODUCTION_URL`; `:36-48` call `setWebhook` on the one bot then `telegram_config_set(notify_url, secret)`. Seed is pinned to prod project `jfvgfbmilavkkdjohmcl` (`demo-seed.mjs:127-130`), so the demo runs against the prod DB. Scenario: demo project gets `TELEGRAM_BOT_TOKEN` + `SUPABASE_SECRET_KEY` copied from prod; someone clicks Settings → Telegram → Connect during rehearsal/on stage; real bot webhook now points at demo; `private.telegram_config.notify_url` in prod DB points at demo; prod push edge function sends real reminders (titles, bodies, member/chat ids) to the demo; real Telegram chats answered by demo. Same mistake enables live Stripe checkout (`billing/checkout/route.ts`) and admin account deletion (`account/delete/route.ts`). **Fix:** on the demo project set ONLY `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` (optionally `OPENAI_REALTIME_MODEL`). Do NOT set `TELEGRAM_BOT_TOKEN`, `SUPABASE_SECRET_KEY`, `STRIPE_*`, `APP_URL` (routes then 503 = safe failure). Hide Settings → Telegram and Plan → checkout from the stage script.

**H1.** `api/assistant/session/route.ts:24,60-89`: no `expires_after`, no rate limit. `assistant.sql:58-60`: a new start closes every open session billing only seconds since start; `:35` only `mode='voice'` billed; `:66,96` text limited only on Life and counted by the client (`components/assistant.tsx:356` calls `ai_message_used`). Any signed-in member can call it; sign-up is open (`signInWithOtp`, `components/auth/email-code.tsx:26`) and each new household gets `plan='together', status='trial'` for 14 days (`rideff_v4.sql:L131-L137,L238`). Exploit: sign up with any email; POST `/api/assistant/session {mode:"voice"}` twice a second apart: DB closes session A (~1 s billed) and returns token B while A's WebRTC call keeps running at OpenAI; repeat for unlimited sessions while `usage.voice_seconds` grows by seconds; "text" token never books voice time and the client can `session.update` to enable audio; Life user can skip `ai_message_used`. Cost limited only by the OpenAI account limit, on a projector in front of an audience. **Fix (smallest first):** (1) `DEMO_ALLOWED_USER_IDS` env checked in `lib/server-auth.ts:17-21` (protects every AI route); (2) in `ai_session_start` refuse while an open session younger than ~90 s exists (`raise 'busy'`) and bill by minting (>=60 s each); (3) `expires_after:{anchor:"created_at",seconds:60}` in the `client_secrets` body, cap `max_response_output_tokens`, server-side tracker ends the call when quota is used; (4) count text messages on the server, not the browser; (5) separate OpenAI **project** key with hard monthly budget for the demo + Vercel Firewall rate-limit on `/api/assistant/*` and `/api/ask` (e.g. 20 req/min/IP).

**H2.** `lib/ask-server.ts:83-85`: `ai_message_used` returns null for non-Life plans -> no cap; `:13` model `claude-opus-5-5`, `max_tokens 8000`, adaptive thinking; `assistant.sql:96` same no-limit return. A fresh OTP account on a 14-day Together trial can loop curl against `/api/ask` with full Opus + household context. **Fix:** reuse the `ai_use` daily-cap pattern for `ask` (kind `'ask'`, ~100/day every plan, in `20261112000000_fase_a_limits.sql:44-48`); same allowlist + firewall as H1; Anthropic workspace with spend limit on the demo.

**H3.** `demo-seed.mjs:158,161,165`, `20261108000000_billing_push.sql:32-52`: `reset_my_data` deletes only from tables with an `owner_id` column. `categories` has no `owner_id` (`money_core.sql:15-25`) so it is never deleted: every seed run inserts 10 more categories; after the second run Budget shows each category twice, summed limits double, Home hero (`flexLeft` = non-fixed limits) jumps to ~double, breaking the "12 → 11 months" storyline. `ai_messages`, `ai_pending_actions`, `ai_sessions`, `usage`, `ai_daily` use `member_id` so aren't cleared: rehearsal chat stays in Ask Clopar history and pending cards (the runbook line at fable-b `:76` and the seed comment `:158` wrongly say the seed clears rehearsal chat). Tom's rows and uploaded storage objects survive. Seeded `recurring` rows have no `last_posted_month`: hourly cron `private.post_recurring()` (`money_core.sql:194-234`) posts every item with `day_of_month <= today` at the next :07 -> ~7 new transactions, "N recurring items added · Rent…" toast (`components/money-data.tsx:128-136`) on first load, numbers change between morning seed and the talk. **Fix in seed:** before inserts `delete from categories` (household scope, RLS), `delete from ai_messages where member_id = me`, and `ai_pending_actions` by status; insert recurring rows with `last_posted_month: <current YYYY-MM>` (INSERT not column-restricted); probe every table first; print the resulting hero value in `--check` to compare with the script.

**M1.** `assistant.sql:74-81` checks ownership only; `private.ai_close` returns 0 silently on an ended session; `api/assistant/end/route.ts:20-50` then always calls Haiku and inserts up to 3 memories. Re-POST same `session_id` with 30 made-up turns = Haiku cost + 3 private memories each, loaded into every later realtime prompt (`session/route.ts:40-44`) = persistent prompt-injection store (own account only). **Fix:** `ai_session_end` returns null/raises when `ended_at is not null` and skip extraction; cap memories per member (~200).

**M2.** `money_complete.sql:257-260` grants object read when a visible `files` row has `storage_path = objects.name`; `storage_path` is client-supplied with no prefix check (`:71`). A member of household B can insert a `files` row pointing at `<A-household>/<A-member>/<name>` and download A's orphaned object; unique violation also reveals path existence. Needs the UUID path, so low-practical/real risk. **Fix:** `alter table public.files add constraint files_path_own check (split_part(storage_path,'/',1) = household_id::text and split_part(storage_path,'/',2) = owner_id::text);` and add `(storage.foldername(name))[1] = (select private.my_household())::text` to the SELECT policy.

**M3.** Credential handling OK: `.env.demo.local` git-ignored (`.gitignore:34`, `git check-ignore` confirms), nothing printed except errors, publishable key + password sign-in under RLS, no service role (`demo-seed.mjs:121-140`). Gaps: project guard (`:127`) is an allow for the prod project (not a production guard); guard 1 only checks member email equals `DEMO_EMAIL`; if the owner's real credentials ever land in `.env.demo.local`, guard 2 can pass because the foundation migration's default household name is `'Household'` (`20261008000000_foundation.sql:18`) which the seed accepts, so `reset_my_data` would wipe the owner's real rows if never renamed. **Fix:** hard-code demo user UUID(s), refuse any other `auth.user.id`; accept only exact name `"Lena & Tom Brandt"` after first run; refuse if any `transactions` row is older than 120 days or >500 rows; note v4 sign-ups name the household after the display name (`rideff_v4.sql:L236`) so a fresh Lena account is never "Household": use a one-time `--first-run` flag.

**M4.** `.vercel/project.json` -> `rideff-life` (prod). Running `vercel --prod` or `vercel env pull` here for "the demo" deploys `satu-ruang` to prod or overwrites local env. Create the demo project from a separate worktree (`vercel link --project rideff-demo`) or always pass `--project`; check `vercel whoami`/project before each deploy.

**Low/Info.** L1 CSP (`next.config.ts:15-31`): `connect-src` has `https://api.openai.com` covering the SDP POST to `/v1/realtime/calls` (`lib/assistant-client.ts:9`); WebRTC media (UDP/TURN) isn't governed by CSP; allows Supabase https/wss; `img-src data: blob:`, `media-src blob: mediastream:`, `font-src 'self' data:` fine; `script-src 'unsafe-inline'` deliberate (`:4-6`), only inline script is `themeScript` (`app/[locale]/layout.tsx:59`, `lib/theme.ts:27`) so a `'sha256-…'` hash could drop `'unsafe-inline'`; CSP built at build time from `NEXT_PUBLIC_SUPABASE_URL` so a demo on another Supabase project must set it before building; `vercel.live` blocked on previews (harmless). L2 offline queue across accounts: `signOut` (`components/app-data.tsx:163-171`) clears PINs/Ask caches but not IndexedDB `ef-offline` (`lib/offline-queue.ts:16-17`) or per-user money/time/finance caches; on a shared laptop user A's queued writes replay as user B: clear the queue on sign-out. L3 service worker (`public/sw.js`) caches HTML/RSC of 33 pages (`:17-24,98-111`), pages are client shells and `/api/*` + Supabase are skipped (`:127-128`) so no authenticated data in Cache Storage; `VERSION="rl-v3"` bumped by hand so the presenter laptop may run old JS until a second load: hard-reload each stage page after deploy or bump per deploy. L4 `/api/inbox` (`api/inbox/route.ts:16-58`) Opus `max_tokens 16000`, unlimited per valid `efk_` key: add `ai_use('inbox')` ~3/day. L5 no zod anywhere; hand-rolled validation reasonable (date regex, `cleanProposal` `lib/assistant-tools.ts:122-135`, kind/size checks on `/api/read`); no SSRF surface (all outbound URLs fixed). L6 `ai_pending_actions.result` client-updatable (`assistant.sql:11`) and `undoCard` replays it (`assistant-tools.ts:262-275`), limited by RLS + `UNDOABLE` list: integrity note only. L7 `private.telegram_links`, `inbox_keys`, `push_keys`, `telegram_config` have no RLS but are unreachable (`anon` no usage on `private`, no grants to `authenticated`): keep `supabase/tests/rls_leaks.sql` in the pre-talk checklist. L8 `.env.vercel.local` holds redacted placeholders (11-char values) + short-lived `VERCEL_OIDC_TOKEN`; `.env.local` only public URL/key + OIDC token; all `.env*` except `.env.example` git-ignored; `backups/2026-11-05-…sql` (0600, git-ignored) is a real-data dump: never open it or the project tree on the projector; `Rideff life.zip` excluded via `.git/info/exclude`.

**Findings:**

2. mut2 misses >=6:1 on soft2/tint and is the colour of the smallest text: `eyebrow` utility (11px bold mono, `globals.css:144-151`, 88 uses), map captions, tool-step meta (`components/shell/voice-caption.tsx:26,29,45,49,61`).
3. 5. Champagne on more than 3 elements per screen (in noir acc = acct = acci): Home has 13 (eyebrow `text-acc` `home.tsx:231`, CTA `text-acct` `:254`, Ask link `:420`, family pill `bg-acc` `:474`, see-all links `:475`, current day `:525`, lock icon `:575`, goal % `:608`; plus dock button `bg-acc` `components/shell/dock.tsx:55`, compass/caption accents); `/map` has 11 (ring `life-map-scene.ts:336`, edges, selected borders, score badge `life-map.tsx:128`, Ask pill `:297`, send `:400`, voice `:423`).

Legible from the back row needs >=10' (ISO 9241-303 prefers 16'+): **>=22 CSS px on a 3 m screen, >=27 px on 2.5 m**. Eyebrows (11px) unreadable; body (15px) readable only from front rows; map labels 9px caps (`life-map-scene.ts:386`), 11.5px (`:393`), 12.5px (`:390`); voice-caption tool steps 11-13px; HUD and presenter 11px. TraceSheet), toast and 3D scene labels sit outside `main` (`components/shell/app-shell.tsx:66-84`) so are NOT scaled, breaking the spec's "no text <16px" in presenter mode.

**Loading/empty/error states during a live run:** Home `ScreenSkeleton` when `!loaded` (`home.tsx:78-83`), shows only with empty cache because money provider restores the localStorage cache first (`money-data.tsx:140-150`); after a reseed the cached rehearsal data shows first then jumps to new numbers (HeroNumber animates the jump).
